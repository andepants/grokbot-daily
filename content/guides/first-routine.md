Most routines that fail weren’t ready to be routines. The work was never done end to end, so the schedule just repeats a half-working process at a time you’re not watching.

The fix is boring and reliable: **task, fix, skill, test, routine**. In that order.

## 1. Do the job once, with the bot, while you watch

Give your bot the real task, with real inputs. Don’t describe what you’d like it to do someday. Watch where it hesitates, which sources it picks, and what it hands back.

## 2. Fix the process, not the prompt

When the output is wrong, correct the *steps*: which sources count, what to skip, what the result should look like. Run it again until two runs in a row come out the way you want.

## 3. Save the method as a skill

A skill means the bot doesn’t have to work out the method again every morning. Name it after the job (“weekly-invoice-check”), not the tool.

## 4. Decide what failure looks like

Write down what the bot should do when:

- a source is down or the data is stale
- the job only partly finishes
- something needs your approval

“Stop and tell me” is a perfectly good answer to all three.

## 5. Test the routine before you trust it

Do one test run and check that it used the right inputs, produced the right output, and stopped where it needed approval. Start the routine **paused**, or watch the first scheduled run yourself.

## 6. Then schedule it

Only now add the time trigger. Check its run history after the first few runs, and keep it quiet on days when there’s nothing to report.

---

**Rule of thumb:** if you couldn’t hand the task to a new teammate with a one-page note, it isn’t ready to be a routine yet.
